🔒 HARD DATABASE PROTECTION (MANDATORY)
🔐 UNIQUE CONSTRAINT (CRITICAL)

Prevent double booking by enforcing:

UNIQUE (teacher_id, meeting_date_id, time_slot_id)

This ensures:

Only ONE booking per teacher per slot

Even if 100 users click at the same millisecond

⚠️ Do NOT rely on UI checks alone.

🧠 BOOKING TRANSACTION FLOW (NON-NEGOTIABLE)

Every booking must follow this order:

1️⃣ Begin database transaction
2️⃣ Lock the teacher availability row for the selected slot
3️⃣ Validate:

Slot exists

Slot is NOT globally blocked

Slot is available for that teacher

Student has NO existing booking
4️⃣ Insert booking
5️⃣ Update teacher availability → unavailable
6️⃣ Commit transaction

If ANY step fails → rollback.

🚫 FAILURE BEHAVIOR

If booking fails due to conflict:

Return HTTP 409 Conflict

Message:

“This time slot has already been booked. Please select another.”

No generic errors allowed.
